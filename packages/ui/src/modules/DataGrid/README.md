# DataGrid

The record table: rows from outside, each value through the field set, and a spreadsheet's keyboard.

## Why it exists

New. Every object's table view (#20), lists (#21) and the import preview's table need one grid that holds a million rows without holding them all. React Aria's `Table` keeps every item in memory and TanStack Table expects the full data array (spec 0003, the data grid), so the grid is built here on TanStack Virtual with column state of its own. The small settings table is `Table`, not this.

## Use

```tsx
import { DataGrid } from '@crm/ui/grid';

<DataGrid
  label="Companies"
  columns={columns}
  pinnedCount={1}
  rows={rowSource}
  getValue={(row, columnId) => row.values[columnId] ?? null}
  getDisplay={(row, columnId) => row.displays[columnId]}
  rowHeader="name"
  selection={selection}
  onSelectionChange={setSelection}
  onColumnsChange={saveColumns}
  onCellChange={write}
  onCellsChange={writeMany}
  cellErrors={refusals}
/>;
```

- Import it from `@crm/ui/grid`, its own entry, inside a lazily loaded route, so it never sits in the first load.
- `rows` is a `RowSource`: `count`, `getItem(index)` (`undefined` while a row loads, which draws skeletons), `getKey`, `onRangeChange` (the rows on screen plus 8 either way) and, optionally, `resolveKeys` so a shift range can span rows not loaded yet.
- Values leave already valid: `onCellChange` and `onCellsChange` receive values their type's schema accepts. A refusal from the data layer comes back through `cellErrors` and shows as the cell's error.
- Columns are `{ id, attribute, width, isHidden? }`. Widths hold inside `size-column-min` and `size-column-max`; start a new column at `columnWidthFor(attribute)`, its type's tier as pixels. The first `pinnedCount` columns are pinned, and `rowHeader` is always first. A computed column shows the function mark in its header, an AI one the sparkle.
- A header's type icon gives way when the name wouldn't fit beside it: it wraps out of the header's one line, out of sight, so a narrow column reads "Close date" rather than "Close d…", and a short name keeps its icon (QA, 22 October 2026). For a pointer that can hover, the menu chevron sits over the header's end, shown on hover, keyboard focus or while its menu is open, so the name takes the whole width at rest ("Company", not "Com"; owner, 31 October 2026); touch keeps it in the row.
- `untitled` ("Unnamed person") is what a row with no name is called: drawn muted in its row header in place of the empty value, and read as its name. "Untitled" when absent.
- `rowAvatar(row)` gives the row header the row's picture, an Avatar before its name (the image address, or undefined for initials): People's photo sits in the Name cell, never in a column of its own. It is 24px (`md`, two initials on the row's hue, owner 31 October 2026: the 16px single letter read as grey), `rowAvatarShape` `circle` for people (the default) or `square` for companies and other records, as on their pages. The row header's name reads in the body's medium weight, first in the row.
- `onRowOpenPage(rowId)` (owner, 31 October 2026): a click on the row header's name, and Enter on it, open the record's page (F2 or typing still edits the name). `onRowOpen` then moves to an "Open in panel" button at the row header's end, shown on row hover (and always on touch), whose name the grid's one tooltip shows, and to Space. Without `onRowOpenPage`, the name and Space call `onRowOpen` as before. Why a variant: the panel had no cue that it existed, and a list where the panel opens on the name hid the page one press further. The button opens as the pointer lifts on it (pressing a row gives it an element of its own, so a click can miss), or on a click with no pointer (a screen reader's).
- `hideColumnLocks` leaves out the headers' read only lock, for a grid whose every column is read only through its attribute (the trash), where a lock on each of five headers only repeated what the screen says. It changes no cell: a column edits or not by its attribute. Why a prop, not a change per attribute: a read only column among editable ones still needs its lock, so only the screen knows when every lock is noise (22 October 2026).
- `errorText` is the error state's sentence, in the screen's words: "Can't reach the CRM" only when the network failed, never for a server fault. A plain "try again" when absent.
- `footer` draws calculations the screen worked out; the grid never computes over loaded rows.
- `calculations` (by column id, `ColumnCalc`: `choices`, `chosen`, `value`, `onChange`) puts a quiet "+ Calculate" in each column's footer cell (`GridCalc`), shown while the cell is hovered or holds the grid's focus, opening a Menu of what the type can work out (Count, Empty, and for numbers and currency Sum, Average, Min, Max, then None); once chosen the cell reads its name and value ("Sum $42,300", "…" while it is worked out). The screen works the value out across every matching record. Why a variant: the per column sums the footer was waiting for (30 October 2026), Attio's and Twenty's footer calculations; only the grid can place a control in its own footer row and open it from its focus model.
- `addRow` (`{ label, onAdd }`) opens the footer's row header cell with a ghost "+ New person", before the screen's count there; a click on that cell, or Enter or Space while it holds focus, calls `onAdd`. It draws the footer even with no `footer`, and nothing with no rows (the empty state has its own New). The footer sits right after the last row when the rows are few and stays in view when they scroll, so the add is always one press from the rows (Twenty's "+ Add New", 30 October 2026). Why a variant: only the grid can put a line after its rows and give it a key in its own focus model; a button below the grid sat at the page's foot, far from short lists. Pass it only to someone who may create.
- `floatingBar` (spec 0022) draws a bar over the grid's foot, inside the grid's frame so it centres on the grid: the BulkActionBar with `placement="floating"` while rows are ticked. Its room (`size-toolbar` plus `space-16` twice) is the scroller's own bottom padding, after the footer, so the footer stays right under the last row of a short list (never a band inside the rows; owner, 31 October 2026), and a focused row scrolls clear of the bar, so it never hides the cell in use (WCAG 2.4.11). It comes after the grid in the tab order. Why a prop: only the grid knows its frame and its scroll padding; a bar placed by the screen centred on the window and covered the last rows.
- `editorProps(column, rowId)` gives a column's reference or file editor its search, uploads, the signed in member and each search result's note (`describeResult`, spec 0014); it is asked per cell with the row's key, so a record search can say what that row links already.
- `onSort` and `onFilter` add Sort and Filter to the column menu. `sort` (`{ columnId, direction }`) names the order the rows are in: that header carries `aria-sort` and the direction's arrow after its name.
- `rowNotes` (row key to `new` or `no-longer-matches`) draws a row's note after its row header's value, through Badge's label form (`<Badge text>`), so it is read with the name ("Ada Lovelace, New"): "New" (a record the person just made, kept first) or "Doesn't match this view" (a row they edited out of the view's filter, kept where they saw it). In a narrow column it truncates, keeping its full text for screen readers. Spec 0006, AC-56.
- `activeId` (with `activeIndex`) marks the row whose record is open in the panel beside the grid (the CRM flow pass, 31 October 2026): the row takes `surface-selected` (a ticked row keeps its blue), carries `aria-current`, and scrolls into view when the open record changes, only if it is out of view, so a held ↓ in the panel carries the table with it. `activeIndex` is the row's place while the screen holds it, which lets the grid scroll to a row it hasn't drawn. Why props: only the grid knows which rows are drawn and how to scroll its virtual body to one.
- `commentCount(row)` draws a comment mark and the record's open comment threads after the name in the row header (Badge's `icon` form, read with the name: "Ada Lovelace, 2 open comment threads"), left out for 0. It shares the row header with the note and never takes the click meant for the name. Why a prop: only the grid places a mark in its row header cell.
- `isCellKnown(row, columnId)` says whether a row holds a column's value yet. An unknown cell draws a skeleton like a loading row (read as "Loading"), doesn't open its editor or toggle by key, and refuses a copy like a row not loaded yet, so a column just shown never reads or copies as empty (spec 0006, AC-55).
- `onEditingChange(isEditing)` runs when a cell editor opens and closes, so a screen can hold back reordering rows under it (spec 0006, AC-56).
- `focusRow` (`{ index }`, a new object each time) moves focus to that row's first cell and scrolls it into view, after any closing dialog has handed focus back: a screen passes the row it just made (spec 0005, "New person"). Why a prop: the grid owns its focused cell, and nothing outside could move it without reaching into its DOM.
- `onAddColumn` (spec 0012) draws a "+" header after the last column, a checkbox column wide: a ghost button named `addColumnLabel` ("Add attribute"), pressed by a click or by Enter on the header (End in the header row reaches it; Down from it lands on the last column). The body draws nothing under it. With `addColumnItems` (`{ id, label, group? }`, the view's hidden columns; items with the same `group` run together under its heading, as a list's table offers "Sales pipeline fields" before "Deals fields", spec 0048, AC-4807), "+" opens a Menu instead (flow pass, 30 October 2026): those items first, each calling `onAddColumnItem(id)`, then "New attribute…" calling `onAddColumn`; Enter on the header opens it too. Why: a "+" that always created let people make a second Email when the first was only hidden. `addColumnLock` (a sentence, the field types pass, 31 October 2026) turns "New attribute…" off at the object's attribute limit: with nothing hidden the "+" becomes a LockReason (the lock, its reason in a tooltip on hover and focus, named by it); with hidden columns the menu still shows them, and New attribute… is disabled with the reason under it. Why: the dialog refused only after it was filled in. `columnActions(columnId)` adds the screen's items after the column menu's own, behind a separator (Edit attribute, Archive attribute, a danger item last), each `{ id, label, icon, isDanger?, onAction }`. `focusColumn` (`{ id }`, a new object each time) moves focus to that column's header once it is drawn and a closing dialog has handed focus back: the column a screen just made. Why variants: the schema's entry points sit on the grid's own header and menu, and a screen can't add a cell or a menu item there; without the props nothing changes.
- `groups` (13 Oct reference batch 4) runs the rows under headers, a list grouped by a status or select: each `GridGroup` (`id`, `title`, `hue`, `count`, `isCountAtLeast`, `start`, `isCollapsed`) draws a line before its first row, tinted in its hue (`tag-<hue>-bg`, its border above and below), with a chevron, its title as a `StatusDot` and its count as a `Badge`, kept at the grid's start as columns scroll. `onGroupToggle(id, isCollapsed)` makes the header a button that folds it. The screen sorts `rows` by group and leaves a folded group's rows out (the data layer's query, so a million rows stay a window), with `start` where each group's rows begin; a folded group starts where the next does. The grid keeps numbering only its data rows (keys, selection, ranges and paste skip the headers), maps them to drawn lines (`grid-groups.ts`), and counts the headers in `aria-rowcount`. Why a variant: grouping is a way to read the same rows, and a second list component would repeat every cell, editor and key. By keyboard each header is a stop in the grid's column of lines, never a Tab stop: Up from its first row (or Down from the row before) reaches it, Left folds, Right opens, Enter or Space toggle, Up and Down move on.
- `onCreateOption(rowId, columnId, label)` (spec 0012, AC-238) hands a select or status cell's editor its `onCreateOption`: the list searches and offers "Create "<typed>"" when what is typed matches no live option, and choosing it ends the edit and calls this. A screen passes it only to someone who may shape the schema; it makes the option and sets it in one write. Why a variant: the editor opens inside the grid, where a screen can't reach it; without the prop nothing changes.
- The add column menu pins its "New attribute…" row at its foot (`MenuSection isPinned`, 30 October 2026), so a long list of hidden attributes never scrolls it away.

## States

- A row's "New" note keeps its width and the name beside it gives way (a long name had it read "N…"); the longer "Doesn’t match this view" may still shrink (QA, 22 October 2026).

- `status`: `loading` (the header, marked busy, with rows at the columns' own widths from the first frame, so the rows that arrive take their place with no jump, their skeleton bars once the loading delay has passed, and "Loading rows" for screen readers), `error` (with `onRetry`) and `no-access` (the locked empty state), both drawn instead of the grid, and `ready`. Retry leaves with the error state: when the grid comes back and focus fell to the page with it, the grid takes focus (or hands it to its cell), so the keyboard carries on there.
- Grouped: headers tinted by hue, open (chevron down) or folded (chevron right, the rows gone, the count kept); every group folded draws the headers alone, with no empty state.
- No rows: the header stays, so the columns and their menus do too, with `emptyState` (or "No records yet") under it.
- A row still loading draws skeleton cells, and so does a cell whose value isn't read yet (`isCellKnown`). A row's note (`rowNotes`) shows after the row header's value, and hides while the cell edits. A read only cell says why (its own reason, or the field set's: computed, set by the system, read only) and never opens; its column's header carries a lock, named "Read only". A row header with no name shows `untitled`, muted. A refused value, from the data layer or a paste, shows the danger edge. Either reason is the cell's description for screen readers, and shows in a tooltip under the cell (never over the header) on hover or keyboard focus; Esc hides it.
- Selected rows take `accent-soft`, and keep it under the pointer, a blue tint apart from the grey hover in both themes; a cell range takes `surface-selected`, so it reads apart from them; the focused cell carries the 1px inset focus ring whenever the grid holds focus, after a click as after a key, the only focus mark while it edits in place (its editor draws none), and keeps it while a popover edits it, so the panel reads as that cell's. A ticked row's checkbox cell takes no ring after a click (its tint and tick say it once), only under the keyboard. A refused cell swaps the ring for the danger edge. Popover editors open under the cell, at least as wide as it and a menu. In forced colours, selection and ranges are outlined in `Highlight`.
- Scrolled sideways, the last pinned column (header and cells) casts an edge over the columns passing under it: the grid sets `--pinned-edge` on its scroller, an inherited custom property the header and cells read, so neither styles the other.
- The focused row and the row being edited stay drawn while they scroll off screen, so focus and a draft survive the scroll.
- One tooltip serves the whole grid: after the tooltip delay on hover, or at once on keyboard focus, it shows a cell's reason, or else the full text of anything cut in it (`TruncatedText`, and chips that mark their label `data-truncated`). Cells mount no tooltip of their own.
- Rows recycle by their place on screen, so a scroll step of any length redraws rows in place, in order, and the header stays as it is. Cells and headers are keyed by their column, so when a sideways scroll drops columns off the start, the cells still drawn stay mounted and the focused one keeps focus. Each row is its own layout box (`contain: strict`), except one being edited, whose error floats below it.

## Keyboard

The ⌘ key on a Mac, Ctrl elsewhere (Mod):

- Tab enters and leaves at the one focused cell. Arrows move a cell; Home and End go to the row's ends; Mod with Home or End to the grid's ends; Page Up and Page Down a screen.
- Enter or F2 edits; typing a character edits and replaces the value. Enter commits and moves down, Tab commits and moves right (Shift reverses), Esc cancels. An edit writes to the record it opened on.
- How each type edits: typed types in the cell, which becomes the input; several emails, phones, domains or links as their list in a popover on the cell, with the add field focused (a typed key starts it); a select or status as its list, open at once on the cell (arrows and Enter choose; a typed key is dropped); the rest in a popover on the cell with its first control focused, where Tab moves between its fields (a member or record search opens at once, starting with the typed key). A rating takes a typed digit or the arrows as a draft that Enter commits.
- Space on the checkbox column ticks the row, and on the header's checkbox ticks or clears the rows on screen. Space opens the record on the row header (in the panel, with `onRowOpenPage`), and toggles a checkbox value. Enter on the row header opens the record's page when `onRowOpenPage` is given, and edits the name otherwise.
- Mod+Enter follows a link in the cell (an email, a website).
- Delete or Backspace clears the cell or range (a checkbox becomes false; a required value refuses).
- Shift with an arrow draws a cell range; Shift with a click extends it. Mod+A selects the rows on screen. Esc clears the range, and with no range the ticked rows.
- Mod+C copies the range as tab separated text, and announces how many cells. Mod+V pastes through each column's type: a full paste says so in a toast (unless `confirmsPaste` is false, when the screen confirms it once the write lands, with Undo); otherwise one toast counts what was left and why (refused, outside the table, read only), and refused cells keep their reason.
- The footer is the last row the arrows reach; it reads, and nothing in it edits. With `addRow`, Enter or Space on its row header cell adds a row; with `calculations`, Enter or Space on a column's footer cell opens its calculation Menu.
- On a header, Alt+Down or Enter opens the column menu: Move left and right, Pin or Unpin, Hide (focus moves to the column that takes its place), and Sort and Filter when the screen handles them. Alt with Left or Right on a header resizes its column and enters resize mode (the menu's Resize item went, 30 October 2026: one less item, and the keys work where the person already is). In resize mode Left and Right step the width by `space-8`, the width is announced and the keys show on the header; Enter or Esc finish, and any other key, a click or a move ends it too.
- The selection count is announced after Space, Shift ranges and Mod+A (by the floating bar instead, while one shows, so a tick is said once), and a cell range's size as it grows.
- By pointer: drag a header to reorder it (the library's drag wrapper, dnd-kit: a lifted copy of the header follows the pointer, and an accent line marks the side it lands on); drag its end edge to resize; double click a cell to edit; click a name to open its record, or a checkbox's mark to toggle it. A row's checkbox ticks on the press, not the click: focusing a row gives it an element of its own, so a press and its release would meet different elements and no click would fire. The column menu opens under its own column, its end on the chevron, and checks the sort in effect. Cells take no text selection, so a shift click draws a range.

## Differences from the artifact

- Column headers are 13px medium (`body-strong`), as the artifact's README asks, not the 11px label they first had (owner decision, 8 Oct 2026).

The artifact's `DataTable` card drew a static table. This is the grid the spec describes: virtualised rows and columns, rows from outside, editing in place through the field set, and column state that leaves through `onColumnsChange`. A select or status opens as its list on the cell, with no popover around it, so one key reaches the choices.
