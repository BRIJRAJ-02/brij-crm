# AttributeSettings

The one dialog that creates and edits an attribute (spec 0012): its name, type, the type's settings and options, API name, description, rules and default.

## Why it exists

New (from the inventory, `0003-inventory.md`, pulled forward from spec 0003's milestone 4 by spec 0012). Settings' Attributes tab, the grid's "+" header, a column's "Edit attribute" and the table's "Add attribute" all create or edit attributes, and each type's settings must be right in one place. No existing component held a type picker, the rules and a default drawn by the type's own editor; a Form in a Modal is what it is made of, so it composes Modal, Form, Field, Select, Checkbox, RadioGroup and the field set's AttributeEditor rather than adding a variant to any one of them.

## Use

```tsx
<AttributeSettings
  isOpen={isOpen}
  onOpenChange={setOpen}
  typeKeys={['text', 'long_text', 'date', 'checkbox', 'rating', 'email', 'phone', 'link', 'location', 'member']}
  members={members}
  isBusy={pending}
  refusals={refusals} // [{ code: 'SLUG_TAKEN', message: '…', attributeId: 'apiSlug' }]
  onSubmit={(values) => save(values)}
/>
<AttributeSettings isOpen onOpenChange={close} attribute={jobTitle} onSubmit={(values) => edit(values.changed)} />
<AttributeSettings isOpen onOpenChange={close} attribute={createdAt} readOnlyReason="Created at is set by the system." onSubmit={() => undefined} />
```

- Presentational: the attribute, `isBusy` and the last answer's `refusals` come in; `onSubmit(values)` hands out what was chosen, with `changed` listing the settings the person touched, so an edit sends only those. The screen talks to the data layer and closes the dialog when the server agrees.
- **More settings** (the owner, 30 October 2026: fewer choices): the main path shows only Name, Type and that type's own settings (options or stages, a number's display, a currency). The API name (editing only), description, Required, Unique, Allow multiple, the default and the rules sit in one `fields` Disclosure, closed on create, open on an edit that set any of them, and open whenever one of them is refused.
- Without `attribute` it creates: the name first and focused, the type picker (`PICKER_TYPES` from `@crm/contracts/values`, in AC-228's order, narrowed by `typeKeys`, starting on `initialTypeKey` when given (a board with nothing to group by starts on Select); Multi select, Link and Phone are the picker's own labels, the rest the field set's), the API name made from the name (`toApiSlug`, never typed, no field), the description, Required, Unique (only for the types the engine can keep unique), Allow multiple (Email, Phone, Member) and the default. Changing the type starts its default, Unique and Allow multiple again. Until the person picks a type (and when no `initialTypeKey` is given), Type follows the name through `typeFor` from `@crm/contracts/values` ("Email" is Email, "Due date" Date, "Stage" Status); `initialTitle` starts the name (Archive and recreate), and `initialDraft` (an import's column) its name and a select's first options, each option taking the next data hue. Editing, `onArchive` draws a quiet danger Archive at the footer's start; `onChangeType` a quiet "Change type…" under the type for a type with a safe change, and otherwise `onRecreate` the old quiet "Wrong type? Archive and recreate" (flow pass, 30 October 2026).
- With `attribute` it edits: the type and Allow multiple read only, the API name read only with a copy button, the rest as they are, and Save.
- **Change type** (the field types pass, 31 October 2026): `typeChangeStep` (`TypeChangeStep.tsx`) is the step the screen passes as `step` once "Change type…" is pressed, in the same Modal as a relationship's: a Select of the safe targets (`typeChangeTargets` from `@crm/contracts/values`, the picker's icons and labels), the target's own setting drawn by the same TypeSettings as on create (a currency's code, a phone's country), and the server's check in Callouts: checking, every value converting followed by what else changes (one success line: "All 1,204 values convert. Unique turns off."), what stops it instead (warning, with `failedLink` to the table filtered to the records whose values don't convert), a failed check with Try again, and the write's refusal. The footer is Back and Change type, which stays off until the check found nothing in the way (`canApplyTypeChange`). The edit form stays alive behind the step (React's `Activity`, hidden), so Back returns to the settings as they were typed, with focus on "Change type…"; the New type Select takes focus as the step opens. Why in this module: it is a step of this dialog, made of the same Select and type settings; no other component held them.
- `readOnlyReason` shows every setting read only, the reason once in a Callout above them, and Close alone (a system attribute, or a member who can't change the schema).
- `relationshipEntry` (`{ label, onChoose }`, #15) adds "Relationship" last to the picker; choosing it calls `onChoose({ title })` with the name typed so far. The screen then passes `step`, RelationshipSettings' `relationshipStep` with that name on this object's side, and the dialog shows it in place of its own settings, in the same Modal: the scrim stays, and Esc or Cancel still puts focus back on what opened the dialog. While `step` shows, `isBusy` is the step's write. Without it there is no entry and no placeholder.
- The default is drawn by the type's own form editor (`AttributeEditor`, `surface="form"`), so it looks and edits as the value does everywhere. A date also offers "Today plus days" (0 to 3,650, refused locally otherwise) and a member "Current user", as a RadioGroup labelled "Default value" above the editor (None, then the kinds): a saved setting, which SegmentedControl, made for switching views, is not. `members` feeds the member picker. An empty editor, or an unticked checkbox, means no default.
- Refusals land on the setting they name by `attributeId` (`title`, `apiSlug`, `description`, `type`, `isUnique`, `defaultValue`, `offsetDays`); anything else shows above the settings. An empty name is refused before anything is sent.
- **Type hints** (the owner, 21 October 2026: help where a label alone isn't clear): while creating, a Status, Member or Domain says under the type what it holds, in one line. The other types' names say it.
- **Type settings** (milestone 3, AC-230), right under the type: a Number's Display (Plain or Percent, a RadioGroup, as the default's kind is: a saved setting, not a view switch), a Currency's default code (a searchable Select, USD until changed; one is always set). They go out as `values.config`, and on an edit `changed` names `config` once touched.
- **Options** (AC-230, AC-236): a Select, Multi select or Status draws the OptionsEditor under the type. On create the dialog keeps them as a draft: a new select opens with one blank row to type in (it waits for Tab, so focus stays on the type picker), a new status starts with the starter stages (`STARTER_STAGES`: Not started and In progress open, Done won), and Create sends them as `values.options`, each with an id from `newOptionId`. Switching between Select and Multi select keeps them. On an edit the options come in as `attribute.options` and each change goes out at once through `optionWrites` (`onAdd`, `onChange`, `onMove`, `onArchive`, `onRestore`, with `pending` and `errors` back), which the editor's hint says ("Options save as you go."); Save keeps the rest. Without `optionWrites` an existing attribute's options are read only. `optionsLimit` shows "N of 500".
- **Rules** (spec 0013, AC-252): the attribute's validation rules, last, through RulesEditor: each reads as the message a broken rule gives, opens in place to its settings, its message and "Only when…", and moves by drag, keyboard or its menu. `attribute.rules` brings them in, `values.rules` sends the list with Save (it replaces the attribute's rules), and `changed` names `rules` once touched. `ruleAttributes` (the object's own attributes) feed "Only when…"; without them a rule takes no condition. `newRuleId` mints each new rule's id. Each rule's settings are checked on Save with `checkRuleSettings` from `@crm/contracts/values`, the server's own check, so a refusal lands on its setting before anything is sent; the server's `rules.<index>.<setting>` refusals land the same way, and one about the list (the 20 rule limit) under it. Changing the type before create drops the rules it can't take. A type that takes no rule (a checkbox) shows no section. Its hint, "Rules wait for Save.", shows only when editing; creating, the rules go with Create attribute.
- **The default of a select or status** offers the options being edited. When it names an archived option, a Callout under it says what new records get meanwhile (AC-236): "Archived. New records get <first live option>." for a required attribute, "… New records get no value." otherwise. A draft option removed before create takes a default naming it with it.

- **An archived attribute's API name** (flow pass, 30 October 2026): `apiNames` (`{ live, archived, onRestore }`) gives the API names the object's attributes hold. A name an archived attribute's API name matches quietly sends the next free one (`freeApiSlug`, `price_2`), so Create works, and a ghost "Restore the archived Price" under the name calls `onRestore('price')` (the screen restores it and closes the dialog). A name a live attribute's API name matches is refused on the name before anything is sent; a server `apiSlug` refusal on create lands on the name too.
- **Unique refused for duplicates**: a refusal coded `UNIQUE_HAS_DUPLICATES` on `isUnique` lands on Unique, and `duplicatesLink` (`{ label, href }`, the object's table) shows as a Link under it, so the person can go and fix the shared values.
- **`rulesNote`**: one read only line (a Callout) under the rules for a rule this dialog doesn't edit, a Required When set through the API. The screen keeps that rule; the line only says it is there.
- It opens as a Modal `form` (560px, 30 October 2026), wide enough for a setting's label and its value, as Attio's Create attribute is.
- **Type settings** (the field polish pass, 30 October 2026): a number's Display is a Select of Plain, Percent and Compact, each with its example ("1,234.5", "12.5%", "1.2M"), with Decimals under it (Auto, 0 to 4); a phone takes a Default country for numbers typed without their code (empty means the language's region's, until a workspace setting exists); a new Currency attribute starts in the language's region's currency (`useRegionDefaults`; the workspace's once a workspace setting exists), not USD.

## States

Create, edit, read only, change type (checking, converting, blocked with the records' link, failed check, refused), busy (the primary spins with its ongoing verb, Cancel is off, and the dialog stays), a type's settings, options (draft before create, written as they change after), a default naming an archived option, an archived attribute's API name (with Restore it), refused (on the setting, or above them; Unique with the way to the table), each default kind, and rules (closed, open, refused on their setting, read only).

## Keyboard

Focus starts in the name. Tab moves through the settings in order. ⌘↵ (Ctrl+Enter elsewhere) submits from anywhere in it; Enter submits from a single line field; Esc closes it unless the server is answering, and focus returns to what opened it.

## Differences from the artifact

Not in the artifact. A Number's Display is a RadioGroup, not the SegmentedControl spec 0012's screens name, for the reason the default's kind is one. Rules are Checkboxes, not Switches: they are saved with the form, and the Switch takes effect at once (its README). The name comes before the type, as the object and record dialogs ask for the name first, so the first focused field is the one to type in.

## Computed attributes (spec 0015)

- `computed` (`AttributeSettingsComputed`) adds Lookup, Rollup and Formula to the picker right after Member, and draws their settings from `ComputedSettings.tsx` in place of the type's settings and options; More settings then holds only the description (a computed attribute takes no Required, Unique, default or rules). Why in this module: they are entries of this dialog's type picker, and their settings are a type's settings.
- A Lookup reads as one sentence, "From [Company] show [Industry]", and a Rollup as "[Count] of [Amount] across [Deals]", each blank an inline Select inside a Sentence, so the fewest choices show and the sentence starts complete (the first side, the first field that fits, Count). Count where adds a FilterBuilder on the related object's own attributes. A Formula is typed in the FormulaEditor, checked as it is typed by `checkFormulaSource` from `@crm/contracts/formula`.
- Each ends with the preview: a small Table of up to 5 records and their values through `AttributeDisplay`, with a Spinner while a newer answer is out, and "Couldn't work out the preview." with Try again when it fails. The screen holds it (`data.computed.preview`); `onDraftChange` hands it each complete definition.
- An object with no relationship to follow shows an EmptyState with New relationship (`onNewRelationship`). An existing computed attribute (`attribute.computed`) shows its kind as its type, read only, and while it has stopped updating a danger Callout "Not updating: <reason>", with Try again after a failed fill (`onRefill`).
- `values.computed` carries the definition; `changed` names `computed` on an edit.
