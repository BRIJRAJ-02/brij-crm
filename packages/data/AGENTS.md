# packages/data

## Overview

The one client data layer. Every screen reads and writes CRM data through it and never calls the network itself. It is a typed oRPC client plus the record store with windows, optimistic writes and live patches (spec 0005); undo and saved views arrive with Client data and state (#6). Tagged `client`.

## Conventions

- The interface is shaped by what screens need, grouped per feature (`data.system.status()`), not by how the API is laid out.
- `apps/web` imports types from here, never from `@crm/contracts`. Export the types a screen needs from here.
- The API sits at `/api/rpc` on the app's own origin, in every environment.
- This package is the backbone of the app: follow `crm-frontend-state` for every change.
- It is in the first load: keep Zod, the Better Auth client and anything heavy out of its static imports (load them with `import()`).
- Change events (spec 0005; spec 0007 milestone 1 adds the watermark and catch up): each event on `workspace:<id>` carries the workspace's `seq`, numbered with no gaps in commit order, its commit time `at`, and names what changed by id (`ChangeEvent` in `@crm/contracts`, one kind per store: `records`, `entries`, `definitions`, `views`, `notes`, `tasks`, `members`, `access`, `jobs`, and the stub `restricted`). The live layer keeps a watermark `W` per workspace, the last contiguous `seq` applied, for the app load:
  - `W` starts at the workspace's head, which `realtime.subscriptionToken` carries. When live is on, the layer reads it before the workspace's first read (`live.prepare(workspace)`, called by the `/w/$slug` route beside `me.get`; every cached read and a view's first count wait for it, at most 5 seconds), and hands that token to the live client once. When live is off nothing asks and nothing waits;
  - a `seq` at or below `W` is ignored (a repeat, or one a catch up already covered);
  - `W + 1` is applied and becomes `W`: handed to its kind's handlers through the live router (`live/router.ts`: `on(kind, handler)`, `onResync(resync)`; `records` refetch the named records, or everything held of the object when `coarse`; `definitions` the object's attributes, or the workspace's objects when it names neither object nor list), unless it is this tab's own write coming back (its `mutationId`), the stub, or a kind this client doesn't know, which only move `W`;
  - a jump past `W + 1` is a gap: after a random 0 to 2 seconds (a late seq that closes it first costs no call), `realtime.catchUp` from `W` fills it from the outbox (events collapsed per kind and object or list), and the events that arrived meanwhile follow in order (at most 5,000 are held; the catch up covers the rest). A read that went ahead without the head (the call failed or took 5 seconds) marks the workspace uncovered: the live client starts from its own token's head and resyncs. A refused catch up (removed) stops trying. A catch up answered `reset` (the outbox no longer holds the range, or more than 5,000 behind) runs every store's resync instead, after a random 0 to 2 seconds;
  - a new subscription catches up from `W` at once; one that came back without recovery (history gone after 5 minutes or 1,000 messages, or a Centrifugo restart) after a random 0 to 2 seconds; so does a tab shown again after 5 minutes hidden. A failed catch up says paused and tries again with backoff. The relay can deliver out of order (Centrifugo runs every command in a batch, so a row after a refused one may land first), which the watermark absorbs;
  - `coarse` records events wait a random 0 to 2 seconds first, once per object however many arrive meanwhile, so a whole team doesn't refetch in step. A reload reads the count and the blocks on screen; other loaded blocks let go and load when scrolled back to. Attributes are read again too, and the app reloads its pages only when a list came back different.
  - Ids are unique per workspace only, and the store is keyed by id: an event acts only on ids a view of its own workspace shows.
  - Change events don't say which ids were created or removed, and spec 0007 doesn't add that (spec 0006's settle rereads a window's count after changes). Until then an id nobody here shows that sorts past the last loaded row is placed at the end; any other is out of sight, and only one minted in the last 10 minutes (UUID v7 carries its mint time: `mayBeNew`) asks for a spread out `records.count`, since an edit to an older record doesn't move it. A delete out of sight leaves the count stale until the next reload (no screen deletes yet).
  - A block that was loading when an event named one of its ids fetches that id again when it lands (ids changed in the last 10 seconds are remembered).

## Gotchas

- The record store is the plain store, not TanStack DB. AC-40's gate (verify.md) found that TanStack DB's own optimistic transactions break the layering rule. A refusal rolls back later edits to the same record. A later edit carries an earlier edit's value as a whole-row snapshot. A new base doesn't show through under a pending edit. An in-flight transaction defers sync writes. So the TanStack store had to keep its own layers anyway, and then cost more memory and time for nothing. It was removed after the gate. To rerun the comparison, check out 4bac1a0 (`packages/data/prototype/`).
- The store keeps a body only while something holds it (a window's block, later an open record page) or a layer waits on it. A loader must put its rows in with `receive(rows, { hold: true })` and the windows let go; a row received with nothing holding it is not kept. After scrolling all 100,000 records in the gate harness the heap was 12.7 MB against the bare grid's 12.5 MB (it was about 70 MB before eviction).
- A view announces at most once a frame. Whoever needs the state at once (the router loader awaiting `ready()`) gets it flushed; tests pass their own `schedule`.
- A 401 clears the records with everything else, so a pending edit leaves with its session. It also stops live updates and forgets this tab's mutation ids.
- Nothing in the browser polls: while the connection is down, Centrifugo's client reconnects with its own backoff and the screens say live updates are paused.
