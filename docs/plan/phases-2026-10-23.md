# Phases (23 October 2026)

You asked to enrich the features, to reuse the logic in the old Timefix code (logic only, never its settings or secrets), and to plan it all in phases. This plan comes from five read only audits of `land/r13` at db1d395d and a read of the old Timefix code. You hand product and UX calls to the builders, who decide and report back. Deploys wait until the end of the run.

The scope in [docs/scope/index.md](../scope/index.md) says what each feature is and where it stands; this page says what comes next. The `#` numbers below are scope features.

## Where we stand

On 23 October the scope was reconciled with the code: 19 features are done, 21 are in progress, 23 are planned and 3 are dropped. Scheduling, forms, the app frame (sidebar, settings, Home, command menu) and the team basics are built. The gaps are the deeper CRM features Attio has (lists, computed attributes, reports), cleaner data, the platform (API, webhooks, automations) and the things a paying customer needs (access rules, plans, billing, backups).

## Phase 0: housekeeping

- **Scope matches the code.** The scope said planned for work that was built. It now follows the code, and this plan is written down here. Lane `wip/scope-reconcile`.

## Phase 1: Attio parity on the CRM

- **Lists and pipelines (#51).** The tables and the engine service exist, but there is no spec, no API and no screen yet, and the sidebar keeps a place for Lists. Spec 0048 first (lane `wip/spec-lists`), then the build.
- **Record page (#17).** A side panel to peek at a record with Previous and Next (spec 0017 milestone 4), a More menu in the header with delete and restore, and comments in the timeline. It starts after `wip/related-sections` lands, since both touch the same files.
- **Board (#21).** Add a card from a column, the stuck in stage badge (spec 0021 milestone 3), and selecting several cards at once. Lane `wip/board-wins`.
- **Table (#20).** Group rows by a field.
- **Command menu (#33).** Act on the open record from ⌘K: assign an owner, change the stage or status, add a task, delete. Lane `wip/cmdk-actions`.
- **Follow a record (#28).** Follow any record and get a notification when it changes (a new notification kind).

## Phase 2: cleaner data (from the old Timefix logic)

- **Duplicate detection and merge (#31).** Port the old duplicate, company match, record match and lead identity logic with its tests. Spec 0049.
- **Import upgrade, like Attio (#30).** Excel files (.xlsx), typed cell reading (yes or no, dates, money, several options; a cell that can't be read is refused, not guessed), and better mapping and review steps, using the old import value reader, spreadsheet reader and field aliases. Lane `wip/import-plus`. You reopened Excel import, which overrides spec 0040's earlier no Excel call.
- **Company from the email domain, everywhere.** Forms filing too, with one shared list of public email domains (Gmail, Outlook and the like) that never make a company.
- **Outcomes.** A lost reason is required when a deal is marked Lost, and the lead source is set from how the record came in, from the old outcomes and lifecycle logic.

## Phase 3: a richer data model

- **Reports and dashboards (#52)**, with pipeline, win rate and response time (from the old response time logic). Spec 0050.
- **Computed attributes (#16):** formulas, rollups and lookups.
- **Attribute groups and layouts (#18).**
- **File attachments (#32)**, stored on R2.
- **Changing an attribute's type (#14)**, with a preview and undo (spec 0013 milestones 3 and 4).
- **Relations (#15):** sort by a related record (spec 0014 milestone 4). The schema map (#56) comes last in this phase.

## Phase 4: scheduling and forms depth

- **Booking embed snippets (#59).** The page editor hands out the code to embed a booking page; the embed script already does inline, popup and a floating button. Lane `wip/embed-snippets`. Any change to the public booking page itself needs your OK first.
- **Booking extras.** Custom booking questions, reminder timing you can edit, Zoom, the team day view (#66, spec 0030), out of office, and the clean up migration left from availability schedules (#64).
- **Forms (#48).** New question types (date, time, rating, scale, address, several options with Other), a Steps layout, filing to a person, a company and a deal at once, a team notice and a visitor confirmation, a funnel with partial answers, and the answers written on the meeting description (from the old lead hand off logic).
- **Calendar repair (#44).** Push a confirmed booking again when its calendar event never got written (from the old calendar repair logic).
- **Round robin (#58).** A fixed host plus the rotation, and owners given by the rotation on import.

## Phase 5: platform

- **Public API with keys (#34)**, then **webhooks (#35)**, then **Zapier and Slack (#49)**.
- **Automations (#53)**, following the old workflow pattern: draft, dry run, approval, then live.

## Phase 6: ready to sell

- **Access rules, teams and the guest role (#24, #23).** These need live updates split by audience first (spec 0007 milestone 4 and spec 0009 milestone 3, which ship together).
- **Plans and limits (#38), then billing (#42).**
- **Backups and a rehearsed restore (#37).**
- **Scale (#41).** The last runs put the slowest responses 5 to 12 times over budget.
- **Legal links in the app** (privacy and terms, part of #36).
- **Operator actions (#39):** suspend a workspace, change its plan, and support access with the owner's grant.
- **Last of all: Gmail.** Email sync and sending from records (#43, #45), then sequences (#46).
