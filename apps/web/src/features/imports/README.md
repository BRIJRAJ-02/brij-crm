# Imports

Spec 0040, milestones 1 to 4. A CSV into any live object, through the browser's reader and the `records.import` job.

## The import page (`/w/$slug/objects/$object/import`, ImportScreen)

- **Purpose**: bring a spreadsheet of records into one object, seeing what each row will do before anything changes.
- **Main task**: choose a CSV, check where its columns go, settle any value that won't read, read the preview, start.
- **Leaves out**: making far records of more than one object for a relation column, and file types other than CSV.

## An import's summary (`/w/$slug/objects/$object/imports/$importId`, ImportSummary)

- **Purpose**: one import's page: its progress while it runs, then what it did, kept for its 7 day undo window.
- **Main task**: see how many rows were created, updated and not imported, and why; undo the import if it was wrong.
- **Leaves out**: editing the import's settings, running it again, and the imported records themselves (View records opens the table on today's new records, newest first, as a draft).

## Notes

- The view bar's Import / Export menu (`views/TransferMenu.tsx`) holds Import <plural> for members who may write the object (`object.access`; the view's menu no longer repeats it, 30 Oct 2026); a member who can only read opening `/import` is told so, with View <plural>; ⌘K has Import <plural> on an object's page. Both pages load in their routes' own chunks, with the CSV reader (`@crm/data/imports`), outside the first load.
- Three steps in a Steps bar, four when a value needs settling (owner walk, 30 Oct 2026): Upload (FileDrop; the reader refuses by type, size, rows, columns, an empty file or an unclosed quote, each with what to do, and an Excel file says how to save it as CSV; the member's Recent imports into the object sit under it, from their jobs, each linking to its summary with its undo window), Match columns (a Table of columns, three sample values and a Select each), Review values (only when something won't read as it is, `ReviewStep.tsx`, `review.ts`) and Preview (totals, how rows find records, All, Ready or With errors, a paged Table, Download rows with errors). Done steps in the bar go back.
- Review values: a select or status label that names no option is created (the default where the member may add options and they fit under 500), mapped to an option it has, or left empty, label by label; a column's cells that don't read are grouped, and left empty by default (Leave these N cells empty) so the rest of each row imports. One Continue makes the options, then reads the rows with the choices.
- Preview's one line for finding records: the object's usual key (Email addresses on People, Domains on Companies), else the first unique attribute a column fills, or Don't match, always add (which warns of duplicates when the object holds records); Fill, Overwrite and Skip, and what a row matching nothing does, sit under More settings. One lookup of the match column's values (`imports.matches`, a read through the access door) counts the rows new, update and skip beside Start, a second row with an earlier row's key counting as an update (`rowPlan`).
- `matching.ts` proposes each column's attribute by header, API name and a short synonym list, then keeps it only when half or more of a 50 value sample reads as the type. One attribute takes one column, and a name whole never sits beside its parts.
- `rows.ts` reads every cell through the field set's `fromText` (the parser paste uses), in the browser's language and time zone, with members by email or name and phones through the phone library. Empty cells are left out, so they never clear a value. A row with a cell that can't be read is an error row, and none of its cells import.
- Start import (no second question: Undo lasts 7 days) makes the import, sends its ready rows in chunks (`data.imports.stage`, a progress bar with Stop, which asks first), starts its job and opens the summary. Leaving before then asks first and drops the file.
- The summary follows the job live (`useJob`): progress with Cancel (asks first), then the counts, the refused rows paged with Show more and Download refused rows, View records, and Undo import (a danger confirm) while undo is open: the `records.import_undo` job moves the created records to the trash (the import's id their batch) and puts changed values back, keeping any edited since ("1 value changed since, kept." on its row). The jobs' end toasts link here.
- `e2e/import.flow.ts` runs the whole loop (5,000 rows at 1280 by default, 300 at phone width; CI runs 1,000 to stay in its time), with axe in light and dark at each step.
- The lean pass: the title sits in the bar ("Import people", "Import of people.csv"), the Steps bar names each step, cards keep short copy, and one InfoTip says what the Row numbers mean (Preview). The summary shows Created, Updated and Not imported (skipped, refused and error rows together); counts of none are left out.
- Leaving with a file loaded, or while rows send, asks in a danger Modal (the router's blocker with its resolver); closing the tab asks the browser's way. Focus goes to the page title at each step, since the pressed button's Card goes.
- Rows are read a slice of 2,000 at a time on Match columns' Continue (a progress bar there), once per file and set of targets, and again after Review values.
- New attribute from a column opens the attribute dialog (`settings/AttributeDialog.tsx`) prefilled: the header as its name, the type the values suggest, and a Select of the values when they repeat and are 20 or fewer (`suggestAttribute`).
- The Background jobs page links an import's job to its summary (View import) and a finished export to its file (Download), from the job's result (`importId`, `exportId`).
- Export (the view bar's Import / Export menu: Export view (N columns), and Export all columns (M) when some are hidden; ⌘K's Export this view; the bulk bar's Export N selected; every member who can read it) starts a `records.export` job with the view as it stands. `export-run.ts` shows one busy toast while the job writes, which turns into Download when it succeeds or into what went wrong with Try again, watching the job through the data layer's job store; `main.tsx`'s finish toast stays quiet for one this tab started.
- Upload offers Download a sample CSV: the object's importable attribute titles as a first row, written in the browser.
- The upload card shows the file's shape as a `SampleTable` picture (row 1 is the column names) instead of a sentence, with Download a sample CSV under it. A relation column's names that match no record are one row, "Company: 3 of 40 not found", with a segmented Create them / Leave empty (31 October 2026: it replaced a checkbox, a hint and three stacked sentences).
- Match columns guards what Start used to refuse (`required.ts`): each required field no column fills and no default fills is a danger row with a Match a column picker, and Continue waits on them, unless Only update records I have is ticked (rows matching no record are skipped).
- Dates (`date-order.ts`): a date column whose values read either way round (03/04/2025) gets a Day first / Month first Select, guessed from the file (a first number above 12 is day first, a second one month first, else the browser's order) with one value read by it ("03/04/2025 → 3 April 2025"). The choice is the reading language the field set reads that column's dates in, on the preview and the rows sent.
