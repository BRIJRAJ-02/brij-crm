# Forms

Captures, Forms (spec 0023, `0023-experience.md`): forms that collect submissions from a link or a site, and add each one to the CRM unless the form keeps them only. The routes are `/w/$slug/captures/forms` (the list) and `/w/$slug/captures/forms/$formId` (the editor: `?tab=` settings, install or submissions, `&state=` and `&submission=` on Submissions, `?question=<id>` to open one question); the Captures frame and its Links · Forms tabs come from the shell.

## Screens

- **The list** (`FormsScreen.tsx`): one LinkCard per form, the same card as Links: a colour edge from the form's id, its submissions ("12 submissions · 2 spam", "No submissions yet") and its link, the Accepting switch ("<name> is live", its hint Live or Paused; turning it off pauses at once with Undo in the toast, as the editor's menu does), Copy link, Open and a menu (Duplicate, Delete, which names the submissions that go with it). A form never published shows "Publish it to start taking submissions", with no switch and no link yet. New form makes "Untitled form" at once and opens it.
- **The editor** (`FormEditor.tsx`): the TopBar holds the name with its status beside it (EditorStatus: Live · v1, Live · edited, Paused or Draft), then the Captures editors' shared header (`../captures/EditorActions.tsx`, the booking page editor's too): Copy link (from the first publish; a draft has no link yet, so it doesn't show, 22 October 2026), Preview (the draft in a new tab, marked Preview, not live), Publish the first time or Publish changes while there are unpublished edits (forms keep a draft; booking pages save directly and never show it), and the ⋯ menu: Pause or Resume (at once, a toast with Undo, 22 October 2026), Duplicate, File earlier submissions again when it applies, then Delete form, which asks first. The name changes in Settings, as a record's name changes in its fields, not from the header. PreviewLayout, the one Captures editor layout it shares with the booking page editor, holds the tabs once published (Form · Settings · Install · Submissions), notices (a read only note, a refused publish, a teammate's change), and the live preview, drawn in a phone in the last third of the width (behind a Preview button that opens a sheet on a narrow window), with Colour and Corners. The draft saves itself a second after the last change; a teammate's save first shows "Bea changed this form. Load their version".
- **Answer types** (spec 0063, AC-6307): beside the first twelve, Date (earliest and latest day), Time, Date and time, Rating, Scale (from 0 or 1 to 5, 7 or 10, with words for its ends), Multi select (least and most picks, and Other), Address and Hidden (a value when the link has none; never required). Each files onto the attribute types `FILES_ONTO` names; a Date and time or an Address has nothing Save could make for it beyond a date, a location or a timestamp field already there. A booking page's questions keep the first twelve (AC-6311). A form holds 50 questions.
- **Prefill** (`InstallTab.tsx`, AC-6309): For developers opens with a Prefill link card: an example link to copy, and every question's key. `?key=value` fills a question; a key repeated fills a multi select's several picks; a hidden question takes it too. A value that doesn't fit is ignored.
- **Layout** (`LayoutCard.tsx`, spec 0063, AC-6302): the Form tab's first card, above Questions, beside the preview it changes: Classic, Steps or One at a time as three picture tiles (TileGrid's choice variant, each a `FormLayoutThumbnail`, what a visitor gets in its tooltip). It lives in the draft and goes live with the next publish, so a visitor mid fill keeps the layout they started in. Steps with no divider yet says where to add one, in one line. Why the Form tab rather than Settings: the preview lives here only, and a layout is chosen by watching it.
- **New step dividers** (`../questions/steps.ts`, spec 0063, AC-6303, AC-6312): in the questions list, each just above the question its step starts at, drawn as QuestionList's `step` kind (on the ground, dashed) and dragged like a question; a question dragged across one changes step. Add a step (a button with Steps, the ⋯ menu otherwise) adds one at the end with its title focused, and the next question added goes under it. Open, a divider holds its optional title and a Show when over the questions before it. Remove step merges its questions into the step above, with Undo. Outside Steps a divider is kept and says "Shows with Steps". Publish refuses an empty step, a step's Show when over a later question, and a Show when on the step holding the email a submission is matched by, opening that divider.
- **Questions** (`../questions/QuestionsSection.tsx`, shared with a booking page's Questions tab since spec 0057): QuestionList cards, closed until opened, with Add a question, presets, Close all, Duplicate, Delete with Undo, and reorder by handle or keyboard. A form that keeps its submissions only shows no filing: no "Where it goes", and nothing about it on the cards.
- **The first publish** (`PublishDialog.tsx`, spec 0058, AC-13 and AC-6): one step, Publish your form. Name and Link (checked as typed), Save to (the objects, New object "<form name>" for `schema.manage`, made as Publish starts with one field per question, so Cancel leaves nothing behind, and "Don't add to the CRM" set apart last), then a Question / Saved as table: each answer is matched to a field by its label as the dialog opens, and each row's small Select stays changeable (a field that fits, a New field Publish makes, or Submission only; the email the form matches on is locked, as on its card). When Publish will make the object's email unique, the footer says so in one line; Enter in Name or Link publishes. Publish turns the same dialog, now named Your form is live, into the Ready panel (`ReadyPanel`, headed by the form's name): the link, Copy, Share and its QR code, then the three embed tiles; no code shows until a tile is picked, and Done (or Esc) closes it.
- **Settings** (`SettingsTab.tsx`): one full width column with no preview (the preview lives on the Form tab only, with its Light/Dark and corners controls), short Cards with one or two word titles and no subtitles: After sending (a compact SegmentedControl Message · Web page · Booking; Booking is always a choice, and with no live booking page it shows an empty state whose Create a booking page is a Button; the booking page gets the visitor's name and email filled in); CRM (Add each submission to the CRM, one short line while it files, Save to, and a Question / Saved as table whose links open their questions); Text (headline, subheading, button); Details (name, link and owner, saved together from the SaveBar, which shows only when changed; the owner of new records is Nobody, a teammate, or a round robin group under its own heading in the same Select, each group with how many teammates are switched on, spec 0029 milestone 3: its one line says who gets each new record, or why nobody will, and a group the reader can't list stays shown, saying new records still go to it); Spam (a Review button). Actions are Buttons; links only navigate. A field still being typed (a partial web address, empty button words) shows its message under the field after it is left, keeps the server's value in the quiet draft save so every other change still saves, and blocks Publish until it is complete. A failed draft save says "check your connection" only when the server wasn't reached; a refusal says what was refused.
- **Install** (`InstallTab.tsx`, spec 0058, AC-11): share the link (Copy link, Open, and an InfoTip on when the link fits and when the snippet does), put it on your site (In the page, Popup or Corner button as three tiles, `EMBED_TILES`, each a picture and a name with what the visitor sees in its tooltip; then the snippet, with Copy on its code block), and For developers, one quiet Disclosure, closed, its cards on the same left edge as the cards above (your own HTML, the sites that may post, signed posts). The Ready panel draws the same tiles.
- **Submissions** (`SubmissionsTab.tsx`): what needs a review on top, then a table (the person: their record, or the name they gave; when; the state, saying Not in CRM or Received for one with no record; their email; the form's next two questions), which scrolls sideways in its own frame when a long value widens it, When and State kept near the start, with search, a state filter, bulk Not spam, Add to CRM and Mark as spam, export as CSV and Sync earlier submissions. A row opens the submission in a stacked Panel (22 October 2026, after Typeform's and Tally's response view and Attio's side panel): the header names who sent it (their record's name, the name answer, or the email) with the form and when under it, and the state as a StatusDot; then Answers, Records and Where it came from, each a FieldGroup headed as an h3, separated by hairlines, every row stacked label over value. Filing is said once after Answers ("3 of 9 saved on the record", `answer-filing.ts`), and the answers not saved are marked Not saved. A phone shows through the field set, spaced for reading; an email or a website stays plain text that wraps (a visitor typed it, so never a link), and all three copy their raw value from a button on hover or focus. Only the answers not saved are marked, the same group on every submission. While it is being added, Records says so in one quiet line. The footer has Delete at its start (danger, asking first in a Modal), and Mark as spam, Add to CRM or Not spam at its end; a failed one shows Retry with Add to CRM and Mark as spam under More.
- **Sync earlier submissions** (`SyncDialog.tsx`, spec 0058, AC-14): one line, Only unfiled (chosen on open) or All as a compact SegmentedControl, the counts as Stats (only those that would happen: new records, updated, unchanged, can't be synced), and one button naming how many it would change, new records plus updates, never the ones that already match ("Sync 12 submissions"; every one in scope when the counts cover only the newest). When every one already matches it says "All 2 already match." with Done and no Sync; with none in scope it says Nothing to sync in one row and offers no button. It runs as a background job followed to its end (`followJobs.ts`).
- **Confirms** (`FormConfirms.tsx`, spec 0058, AC-18): Delete form, Rotate secret, Remove site and the object change each stay a confirm Modal with the question, one line under 12 words, and two buttons.
- **Empty list**: a still drawing of a form (`SpotIllustration`), "No forms yet", one line and New form, a secondary: the TopBar's New is the one primary.

## Rules

- `draft.ts` holds every change to a draft as a plain function; `draft.test.ts` checks them.
- The publish check is `publishProblem` from `@crm/data/forms`, the server's own.
- "Submission" is the one word for what a form collects, in every string here.
- The visitor's page is `src/public/main.ts`, drawn by `@crm/ui/public-form` with React and the library's own controls, under its budget in `apps/web/.size-limit.js` (223 kB of JavaScript and 17 kB of CSS gzipped). Steps and One at a time are their own lazy chunk, at most 10 kB, which a Classic form never loads (spec 0063).
