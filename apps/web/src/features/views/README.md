# Views

One screen shows any view of any object (spec 0020): the TopBar, the ViewBar with the switcher, the Toolbar with the view's sorts and filters, and the table.

## Brief

- **Purpose**: slice one object the way you work and keep it.
- **Main task**: filter and sort the table, then save it.
- **The default order** (owner, 22 October 2026): Created at, newest first, runs silently with no chip, whether the view stores no sorts or exactly that one (`isDefaultSort` in `query.ts`), as Attio, Notion and Linear leave their default order unsaid. A chip shows only for another order, and removing it goes back to the default. The dashed Sort button opens the builder empty, saying "Newest records show first.", so Add sort starts a sort of its own rather than adding after a Created at nobody chose. A draft is compared with the default order written as no sorts (`withDefaultOrderAsNone`), so a view storing Created at newest first and one asking none are never a draft of each other, and a row edited into the default stays in the open builder. Filters have no default, so every filter chip is one someone chose.
- **Leaves out**: grouping inside the table, view search, charts, sharing outside the workspace.

## States

Loading (the object page's skeleton bars), not found (`viewNotFoundPage`, never saying why), no view available (`noViewsPage`), error with Retry (the route's error page, or the grid's own when its rows fail), an object with no records, a filter matching nothing ("No people match these filters" with Discard changes on a draft or Edit filters on a saved view), and an archived object (spec 0012's page).

## Known limits

- **Undo of a deleted view** (the CRM flow pass): Delete is hard on the server, so the toast's Undo makes the view again from this tab's copy of it (same id when free, else a new one). That copy is what the deleting person could see: columns a field rule hides from them are not in it, so a view deleted and restored by someone who can't see every field comes back without those columns, and its place, lock and default don't come back either.
- **A kept draft** (the draft this tab keeps for a view, brought back with no `draft` in the address) goes through the same check as a link's in the route's loader: one that no longer reads is dropped with the same toast, and a condition on a field archived since is left out with the dropped notice rather than sent.
