# Booking pages (spec 0025)

## Captures › Links (`/w/$slug/captures/links`; the old `/settings/booking-pages` redirects here)

- Purpose: the member's booking pages (an admin sees everyone's) with their status and bookings this month (AC-645).
- Main task: make a page and open its builder; copy a link, pause or take bookings again, delete one after a confirm.
- Leaves out: a page's settings (its builder), the bookings list (milestone 2) and team pages (milestone 3).

Built from Table, Badge, CopyButton, Button, Modal (new page, and the delete confirm with `tone="danger"`: Delete page stays busy until the server answers while the card has already left, a refusal shows inside it with the card back, and once deleted focus goes to the page's title), Field, Callout and EmptyState. Pause shows at once and rolls back on a refusal.

## The builder (`/w/$slug/captures/links/$pageId`; the old `/settings/booking-pages/$pageId` redirects here)

- Purpose: one page's details, meeting lengths, location, availability and limits (AC-623, AC-624).
- Main task: change a setting and have it saved half a second after the last change; what failed is said where it happened.
- Leaves out: questions and the deal step (milestone 2), team members (milestone 3) and a live preview of the public page.

Cards of Switch, Field, Checkbox, Select and DatePicker. The Hours card picks the schedule the page books by (spec 0035, AC-965): the default schedule by its name with a Default badge, which follows whichever schedule is the owner's default at each slot read, or one of the owner's schedules by name, then says that schedule's week and zone; Edit hours opens that schedule's editor. The owner's schedules come from the data layer's held list (`data.schedules.view`), so a save elsewhere shows in the card. While the reader has no calendar connected (`data.calendar.view`, read through `useCalendar`), a Callout says the page offers their hours minus its bookings (AC-631), with a link to Settings, Calendar when sync is on here. The editor sits in PreviewLayout, the one Captures editor layout it shares with the form editor: notices above, then a Tabs strip at the top of the left column, one tab per group (Page, Meeting, Hosts on a round robin page, Hours, Limits; the owner, 22 October 2026: the stacked cards were too much to look through), each a `fields` TabPanel with no Card around it, beside the sticky preview (the page in a frame, Phone, Tablet or Desktop wide, the same on every tab, since each group shapes the visitor's first step), and the save bar in its `footer`. The tab is in `?tab=` (`pageEditorHref(slug, id, tab)`, `PAGE_TABS` in `links.ts`), replaced rather than pushed, and the loader doesn't rerun on a tab change. A tab whose fields hold an error, or which a refusal names, carries the Tabs `alert` dot.

Who can book (Page tab) is Public or Link only, one SegmentedControl in a FieldGroup with one line that changes with the choice. There is no booking profile, so every page is reached by its link: Public books inside the hours and limits, and Link only (`isPrivate`, one combined flag) also books reserved time and ignores the minimum notice; the lists tag a link only page "Link only" and public pages carry no tag. The header is the Captures editors' shared one (`../captures/EditorActions.tsx`): Live or Paused beside the name, then Copy link and a ⋯ menu with Pause or Resume (at once, a toast with Undo), Duplicate, and Delete booking page (`DeletePageDialog.tsx`, shared with Links).

The Meeting tab ends with Add bookings to (`PageDestination.tsx`, spec 0024 AC-997): for the page's owner, Default (naming it, its note a muted line under it in the list) then each calendar they can write, built by `calendarOptions` (`../calendars/calendar-options.ts`, shared with Settings › Calendars): flat for an account with one, under its address for an account with two or more, each dot in the calendar's own colour, saved at once like the Live switch; an error when the chosen calendar can't take bookings now (they go to the default); a colleague reads it only, never a name (spec 0037). The Hours tab (22 October 2026) puts every label above its content: the Schedule select, then Weekly hours (the library's FieldGroup: the chosen schedule's week, one row per run of days with the same hours, `weekGroups` in `hours.ts`, Calendly style, with a quiet Edit to that schedule in Availability and the zone as a person says it, "Kolkata time (GMT+5:30)", `zoneDisplay` from the public page), Reserved time on a link only page, then Checks for conflicts in (`PageConflicts`: the calendars that hold the page's times back as Badges in their own colour, from `calendarOptions`, with Manage to Settings › Calendars, or No calendars connected with Connect calendar). The Limits tab shows every setting as rows (the library's SettingsRowGroup: Buffers, Booking window, Pace), each with an InfoTip saying what it does with an example; nothing folds away (the owner, 22 October 2026: show all upfront). Every tab's fields stay within `size-column-max` from the start edge (TabPanel `fields`).

## Availability (`/w/$slug/bookings/availability`, spec 0035)

- Purpose: the open schedule's editor, the Calendly way (22 October 2026): the default opens first, `?schedule=<id>` opens another (AC-969, AC-970).
- Main task: change the weekly hours (add or remove a day's ranges, copy them to other days), the time zone or the days off, each saved as it changes; switch, make, rename, set as default, duplicate or delete a schedule from the switcher.
- Leaves out: a list of schedules as rows (the switcher's menu lists them), which schedule a page uses (each page picks in its own editor) and a calendar view of a schedule.

The head row (SectionBar) holds the switcher (`ScheduleSwitcher.tsx`: the open schedule's name as a menu button, Default beside it; the menu lists the schedules to switch to, New schedule, then This schedule's Rename, Set as default, Duplicate and Delete, an item it can't take disabled with its reason) and the time zone Select at its end. Below, the week (HoursEditor) and, beside it, the days off (DaysOff) and Used by (the pages booking by it, each opening its editor). New schedule stays the TopBar's primary too; at 20 schedules both wait and say why. The old `/bookings/availability/$scheduleId` address redirects into the tab.

Saving follows the owner's save rule (21 October 2026): the hours, the zone and the days off save as they change (`useScheduleAutosave` in `scheduleDraft.ts`), half a second after the last pick so a run of picks saves once, one save at a time, each naming the version the last stored. Each landed save says "Saved <name>." in one quiet toast with Undo (a newer one replaces it); a failure keeps the hours on screen with Try again; one beaten by another tab or person (`STALE`) shows theirs and says so. A range that doesn't read yet waits on screen, unsaved, with the editor's own error. The name is a text field, so Rename asks in a Modal with its own button. The schedules come from the data layer's held list (`data.schedules.view`), so another tab's save shows within a second. Until the member saves any hours, the list holds the virtual default, "Working hours", weekdays 9 to 5 in the browser's zone (AC-963), which opens like any other and is stored by its first change.

An admin (`booking.admin`) has a Viewing Select at the strip's end: their own schedules or a colleague's by name (`?member=`, AC-971), the choices from one service (`data.schedules.members`). A colleague's confirms and toasts say whose they are ("their default"); a day off's note stays its member's alone, so an admin sees the days without the reasons, and the server keeps the reasons through an admin's save.

Deleting asks first (the owner's confirm rule, 21 October 2026): "Delete the Evenings schedule?", one sentence naming the pages it moves to the default and that it can't be undone, Cancel (Esc) then Delete schedule. The dialog waits for the server and says a refusal inside itself; once it's gone the tab opens the default. The default can't be deleted: its menu item says to set another first.

The page editor's Hours card picks the default schedule (its name with a Default badge, `scheduleChoices` in `schedules.ts`) or one of the owner's schedules, says its week and zone, and links to it (Edit hours). The copy is in `schedule-strings.ts`, apart from `strings.ts`, so it never loads with the route loaders.

## The public page (`/b/<publicKey>`)

See `src/public/booking/README.md`: its own small bundle with plain inputs and the tokens compiled in, per spec 0023's visitor rules.

## New booking page (22 Oct 2026)

`NewPageDialog`: Title, Duration (a compact SegmentedControl with a visible label: 15, 30, 45 or 60 minutes, or Custom, which shows a Minutes field: 5 to 480 in steps of 5, the same bound as the contract and the database check from migration 0062) and Schedule (the same `scheduleChoices` as the editor, one sentence InfoTip), then Cancel and Create page. No web address field: the server makes a free slug from the title, and no visitor sees it since links use the page's key, so the editor drops its Short name field too. The page takes one length here; more are added in the editor, whose Durations chips show the ready picks plus the page's own custom lengths, with a "+ Custom" chip at their end (ChoiceChips `end`) that opens a Minutes field in a Popover (at most four lengths, as the public page shows four; the contract refuses a fifth, `durations.ts`).
