# Hospitality

The Hospitality suite's screens (spec 0065). H0 holds the setup the apps share; each app's own screens arrive with
its slice (Menu H1, Menu QR H2, Table seating H3 and H4).

| Screen                   | Brief                                                                                                                                                                                                                                                                                                                 |
| ------------------------ | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `AppsScreen.tsx`         | Settings › Apps (AC-6501 to AC-6506): one card per app, Install (the business card the first time, Menu with Menu QR in one step) or Installed with Remove, which asks first. Nothing about the apps shows until Timefix opens early access.                                                                          |
| `BusinessCardDialog.tsx` | The first install's one short card: name, kind, the first place's address, time zone and currency, prefilled from the workspace.                                                                                                                                                                                      |
| `BusinessScreen.tsx`     | Settings › Business (AC-6507, AC-6508): the profile, saved with Save, then the places as rows (name, address, today's hours, tables), each opening its page.                                                                                                                                                          |
| `PlaceSections.tsx`      | The top of a place's page: its week of hours (the library HoursEditor with `pastMidnightUntil`, saved as each changes with a quiet Saving… then Saved; hours that don't hold together stay as typed with why), special days (removal with Undo), and details (Save in the card's footer).                             |
| `FloorScreen.tsx`        | One place's page (AC-6508, AC-6509): PlaceSections, then its resources, named for the kind it mostly books (tables, rooms, chairs: Add tables with a Kind select "T1 to T10" with the run as the To field's hint, drag to reorder, an Online switch per row, select several for Area, Online, Offline or Archive, Edit, Archive with Undo, Delete asking first; a lock says why at 300) and its areas. |
| `ComingScreen.tsx`       | Menus, QR codes and Reservations until their apps arrive: shown only while the app is installed, else not found.                                                                                                                                                                                                      |

Data comes only from `data.hospitality` (`packages/data/src/hospitality/store.ts`): every write shows at once where
it can and goes back with the server's reason when refused.

`BusinessPageScreen.tsx` (spec 0066, B4 lite) is Settings › Business › Page at `/w/$slug/settings/business/page`, linked from Business: the page's address (claimed at once), the gallery (FileDrop, a description per photo, move and remove, the BusinessGallery preview), About and amenities, each place's address and search listing, then Publish, which stays disabled with a one line Callout and a link to fix while the page would be broken. Every other change is a draft (`data.businessPage`, `packages/data/src/business-page/store.ts`) that guests never see until Publish; Discard asks first. Picture picks go through one function per kind in `business-photos.ts` (`pickGalleryPhoto`): each photo added opens the shared cropper (`usePhotoCrop`, shape `free`) and is drawn with `preparePhoto(file, 'picture', crop)`; a photo already in the gallery has Adjust crop, which crops it again from its stored copy and puts the new picture in its place, description kept.

`../menu-qr/QrScreen.tsx` is the Tables page at `/w/$slug/qr` (the sidebar's "Tables"), in checklabs' Tables page's flow (owner, 5 Nov 2026): Download all and Add table in the bar; a line of help under the title; the Zones chips (All, each zone with its colour dot, `zones.ts` picks a colour from the zone's name, then Unzoned last, with counts; the chosen chip again shows all, and another zone starts a fresh selection); "12 of 20 tables · 2 selected" with Print QR sheet (the ticked rows, else the zone shown, else every table: `?tables=` on the print page, left out for all of them) and Clear; then one card per zone, A to Z with Unzoned last, each a table of its tables in reading order (T2 before T10): a tick, the table's own label, Seats, its whole code, then QR and Edit, and ⋯ with View menu, Analytics (its scans in 30 days), New code… and Delete. At a phone's width a row keeps its label, its code and ⋯ (QR and Edit move in). `TableDrawer.tsx` is Add table and Edit table in one drawer: One or Several (today's run, "T1 to T10"), Label ("e.g. T12, Bar 3, Patio A"), seats as Fewest and Most, Zone, whose picker makes a zone typed into it (made once, as the drawer saves), and on edit the code and link to read; Create table, Create N tables or Save table, and a toast naming the table. The QR drawer holds the code large, its Code and Link to copy, Open menu, SVG and PNG. `QrPrintScreen.tsx` prints the tables asked for in the page's order as tiles (six an A4, the default) or tent cards, each with its label and code, under "8 tables · scan-ready". The place page calls areas zones too, and tables in none Unzoned. Deviations from checklabs: no Venue or Menu column (one menu a place here), Seats as a range, no Status (archiving lives on the place's page), Analytics is a small dialog of the table's scans until Insights has a QR panel, and the code shows as it is printed (base64url is case sensitive, so never upper cased).
