# apps/web

## Overview

The single page app behind login (React 19, Vite 8, TanStack Router), hosted on Vercel, where a small Routing Middleware proxies `/api/*` to the API, so the browser only ever talks to one origin. Tagged `client` for `pnpm boundaries`, so it may never import server packages.

## Key files

| File | Owns |
|---|---|
| `src/main.tsx` | Loads `@crm/ui/styles.css` first, creates the toast queue, the data layer (sign out on a 401 goes to `/sign-in?redirect=`; a session change clears the router's cache), the theme controller and the router, puts `data`, `theme` and `toasts` in router context, moves focus after each route change and keeps the tab's title on the page's h1 (`features/navigation`), and wraps the app in `UiProvider` (browser language, time zone, router links, toasts) |
| `src/routes/` | File based routes. Each route has a loader, a pending component and an error component |
| `src/routeTree.gen.ts` | Generated by the router plugin. Never edit it by hand |
| `src/features/<feature>/` | The screens for one feature, with a README holding each screen's brief: `auth` (`/sign-in`, `/verify`), `welcome`, `workspace` (the `/w/$slug` frame and object pages), `system` (`/status`, not found) |
| `src/features/navigation/` | Helpers, not a screen: focus after a route change (`focus.ts`: the h1, or the one field on `/sign-in` and `/verify`) and the tab's title (`title.ts`: "<h1> · CRM") |
| `e2e/*.flow.ts`, `playwright.config.ts` | The flow tests (Playwright) against a running app, reading sign in codes from Mailpit |
| `middleware.ts` | Vercel Routing Middleware (Edge): rewrites `/api` and `/api/*` to `API_ORIGIN_INTERNAL`, replacing the forwarded host, protocol and client IP, and the edge secret (`x-crm-edge` from `EDGE_SECRET`; a client's copy never passes; in preview and production, no secret means 503) |
| `vercel.json` | Single page app fallback, the Content Security Policy and caching headers, and Git deploys switched off |
| `public/theme-boot.js` | Applies a saved Light or Dark choice before first paint. `index.html` loads it first, as a plain blocking script |
| `first-load.ts` | The files a first visit loads: the entry chunk and its static imports, read from Vite's build manifest |
| `.size-limit.js` | `pnpm size`: the first load budget, 250 kB of JavaScript and 40 kB of CSS gzipped. Raising it is a spec change |

## Commands

```bash
pnpm --filter @crm/web dev        # :5173, proxies /api to the api on :3000
pnpm --filter @crm/web build      # to dist/
pnpm --filter @crm/web typecheck
pnpm --filter @crm/web test       # the middleware, the built page (layer order, fonts, boot script order, the first load) and the theme boot script
pnpm --filter @crm/web test:flow  # the flows, against a running app (`pnpm dev`); FLOW_BASE_URL for another port, FLOW_SCREENSHOTS=<dir> for pictures
pnpm size                         # from the repo root: builds the app, then checks the first load budget
vercel build                      # from the repo root, after `vercel pull`: the real Vercel output in .vercel/output
```

## Conventions

- Screens get data only from the data layer in router context (`context.data`), usually through a route loader. Never `fetch`, and never import `@orpc/*` or `@crm/contracts` here. Types come through `@crm/data`. See `crm-frontend-state`.
- Lint refuses `className`, `style` and stylesheet imports anywhere in `src/`. If a screen needs a look the library doesn't have, add a variant in `packages/ui`. The library's root stylesheet, `@crm/ui/styles.css`, is imported once, in `main.tsx`.
- Every screen file opens with a three line brief comment: Purpose, Main task, Leaves out. See `crm-design-system`.
- UI comes only from the component library (`packages/ui`; its base styles and the Icon came with #3, the components are arriving with #4), using tokens only. The current status page has no styles of its own on purpose.
- A route's error component offers a retry that calls `router.invalidate()`, so it recovers without a page reload.
- Public URLs are baked in at build time as `VITE_*` variables. Turbo includes `VITE_*` in the build hash.

## Gotchas

- In `vite.config.ts`, the router plugin must come before the React plugin, and `uiVite()` from `@crm/ui/vite` must stay, so the library's CSS module classes keep their `ws-` names. `build.manifest` must stay on for the first load budget.
- Cascade layers take their order from first appearance, and Vite links a shared chunk's CSS (component modules) ahead of the entry's (the reset). So the order comes from `/layers.css`, which `layerOrder()` from `@crm/ui/vite` emits from the root stylesheet's own `@layer` statement and links ahead of every bundled stylesheet. Keep that plugin in `vite.config.ts`, and keep `@crm/ui/styles.css` the first import in `main.tsx` (`build.test.ts` checks both).
- Keep `NODE_ENV` out of the root `.env`. Vite reads that file, and `NODE_ENV=development` there makes `pnpm build` ship React's development build (`pnpm size` refuses it).
- A route's loader stays in the first load (only `component`, `pendingComponent`, `errorComponent` and `notFoundComponent` are split), so a loader imports helpers, never a screen module. The root route isn't split, so its not found page loads through `lazyRouteComponent`.
- The first load may only hold static imports. The grid, editor, charts and schema map are loaded lazily, and `build.test.ts` fails if one reaches the entry's static graph.
- The CSP in `vercel.json` allows only `'self'`. Adding Centrifugo, Sentry or PostHog means adding their origins there, or the browser blocks them.
- The same CSP blocks inline scripts, which is why the theme boot script is a file in `public/`. Keep it a classic script (not a module, not `async`) loaded before the stylesheet and the app, and keep its `crm.theme` key equal to `THEME_STORAGE_KEY` in `@crm/ui/theme` (`theme-boot.test.ts` checks it).
- `API_ORIGIN_INTERNAL` is never in the repo. Production's lives in the Vercel project's Production variables; each preview gets its own from `preview.yml` (`vercel deploy --env`). Locally, Vite's dev proxy stands in for the middleware.
- The middleware reads `API_ORIGIN_INTERNAL` at runtime (Edge), and answers 503 `API_UNAVAILABLE` when a deployment has none.
- Deploys only come from the Actions (`vercel.json` turns Git deploys off). Previews sit behind Vercel's login; production is public.
- The API's host address is public, so the forwarded headers the middleware sets can be faked by calling the API directly, unless the edge secret is in place: Vercel's Production `EDGE_SECRET` must equal Railway production's, and its Preview one (a different value) Railway `preview-base`'s. With a secret set, the middleware answers 503 for a malformed secret or a non https `API_ORIGIN_INTERNAL`; without one, it answers 503 `API_UNAVAILABLE` whenever `VERCEL_ENV` is `preview` or `production`, since the API refuses such a request anyway. Roll it out API first, then Vercel, then Railway (spec 0005, build plan step 2), or production answers 403 to everyone.
