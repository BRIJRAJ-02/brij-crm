TimefixApp is the whole Timefix app as one prototype, built module by module in the new design language: the sidebar from `app-ia.md` (Home, Inbox, Tasks, Notes; Records; Lists; Bookings; Forms, Link page, Insights; Settings), ⌘K over records, pages and actions, Home, and each module as it is rebuilt.

**Use it for**: reviewing the product end to end and the flows between modules. **Don't use it for** a single module's states (each module's own component and demo).

**The consumer provides**: `initial` CRM data (Northwind by default, see `data.ts`) and `start`, the page it opens on. Bookings is BookingsFlow inside it, kept mounted so its state survives moving around the app. A record's side panel lists Meetings with that person (by email, else name), the deal's contact or the company's people, upcoming first then the last three; each opens its booking in Bookings, with its outcome tagged. A deal moved to Lost from anywhere (table, board, record, bulk) asks once why it was lost (Price, Went with a competitor, Timing, No decision, Not a fit, Other, and a note), or Skip; the deal page then shows Lost reason and Lost note. Tasks take a priority (high first in each group) and, with a due day, a repeat rule; ticking a repeating task adds the next one.

**States**: Home with the setup checklist, today's meetings (from Bookings), my tasks and four numbers; modules not rebuilt yet say so and lead home.
